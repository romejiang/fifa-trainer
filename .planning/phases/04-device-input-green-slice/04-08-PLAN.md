    **A. `mobile/src/core/onboarding_flow.gd` —— 只加「软重试」这一个概念，不动状态集合。**

    新增常量与字段：
    - `const SOFT_RETRY_LIMIT := 2`（2 次重来；第 3 次才硬失败）。
    - `const SOFT_RETRY_CODES: Array[StringName] = [&"ambiguous_axes", &"not_enough_samples", &"not_enough_travel"]`。
    - `var soft_retry_count: int = 0`（当前这一步已经软重来过几次）。
    - `var last_reject_code: StringName = &""` 与 `var last_reject_message: String = ""`（最近一次被拒的码与技术原文；屏幕用它决定第二行写什么，logcat 用它留证）。

    `submit_probe_step(result)` 的失败分支改成三段：
    1. 先把 `result` 的 `code` 与 `message` 写进 `last_reject_code` / `last_reject_message`；
    2. 若 `code` 在 `SOFT_RETRY_CODES` 里且 `soft_retry_count` 小于 `SOFT_RETRY_LIMIT`：`soft_retry_count += 1`，**保持 `state` 不变直接 return**（窗口由屏幕清空，用户立刻重试同一步）。此分支**不写** `probe_failure_code` / `probe_failure_message` / `retry_state` —— 那三个字段的语义是「流程停在这里了」；
    3. 否则走今天的硬失败分支（`state = STATE_PROBE_FAILED`、`probe_failure_code/message`、`retry_state = step_state`）。

    交叉校验失败分支同样先写 `last_reject_*`，再判断软重试：`soft_retry_count` 小于 `SOFT_RETRY_LIMIT` 时 `soft_retry_count += 1`，把 `retry_state` 设为 `_cross_retry_state(code)`，并把 `state` 直接置成那一步 —— `STATE_PROBE_UP` 时与 `retry_probe_step()` 同一规则（`_has_rest` 为真回 `probe_up`，否则回 `probe_rest`）。四步结果保留在 `_steps` 里，重测同一个键会覆盖它，因此下一次提交仍会走到交叉校验；不整轮清空。

    成功分支：`soft_retry_count = 0`，并清空 `last_reject_code` / `last_reject_message`。

    以下入口也必须把 `soft_retry_count` 与 `last_reject_*` 归零：`begin_probe()`、`retry_probe_step()`（用户按 B 是一次全新的开始，重新给 2 次机会）、`on_device_list_changed()` 命中新设备时、`on_device_lost()`、`_clear_probe()`。**唯一实现放进 `_clear_failure()`**：上面这些入口里有四个最终都会走到它（`_clear_probe()` 也调它），所以不要在别处再抄第二份清空逻辑；`_clear_failure()` 从此同时负责「清掉这一轮的失败文案」与「清掉软重试计数」。

    **B. `mobile/src/ui/onboarding_screen.gd` —— 三块纯函数 + 三处渲染。**

    新增常量：`const READOUT_MIN_DELTA := 0.2`、`const READOUT_REFRESH_SECONDS := 0.1`。

    新增**静态**函数（`preload` 后可直接调，Task 3 的套件就靠这一点）：
    - `static func direction_word(key: StringName) -> String`：up→上、right→右、down→下、left→左，其它→这个方向。
    - `static func live_readout(raw: PackedFloat32Array, rest: PackedFloat32Array) -> String`：逐轴算 `raw[i] - rest[i]`（`rest` 为空按 0 处理），取 |delta| 最大者。
      - 最大值小于 `READOUT_MIN_DELTA`：返回「你推的是：没有推动（最大变化 %.2f）」。
      - 否则返回「你推的是：轴 %d 的%s（%.2f）」，第二参数是「正方向」或「负方向」，第三参数是**有符号**数。**不得**在这里断言哪根轴是 X 还是 Y —— 轴序号只能由探针给出（INPUT-02）。
    - `static func plain_rejection(code: StringName, key: StringName, attempt: int) -> String`：

      - `not_enough_travel` →「推得不够远：把右摇杆推到「%s」到底再按住」；
      - `not_enough_samples` →「松得太快：推到「%s」后保持不动约 0.3 秒」；
      - 其它 →「这一步没测出来：把右摇杆推到「%s」到底再按住」。
      - `attempt` 大于 0 时句尾追加「（第 %d/2 次机会）」；`attempt` 不大于 0 时追加「（已经试了 2 次仍不对）」。
