> Per-phase validation contract for feedback sampling during execution.

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | 无第三方框架；手写 `SceneTree` runner（`mobile/tests/core_runner.gd`），`Reporter` 内嵌，套件显式 `preload` 注册 |
| **Config file** | 无独立配置；入口就是 `mobile/tools/test-core.sh` |
| **Quick run command** | `bash mobile/tools/test-core.sh` |
| **Full suite command** | `bash mobile/tools/test-core.sh && bash mobile/tools/gate-a.sh && bash tools/check_desktop.sh` |
| **Estimated runtime** | quick ~40 s（含一次 `--import`）；full 3–6 min |

**判据（不可放宽）：** stdout 哨兵 `^TESTS_DONE failures=0$` + 拦截 `^TESTS_ASSERTIONS=0$` + 180 s 看门狗。退出码永不单独作判据 —— Godot 解析失败 / `class_name` 解析失败都返回 0。

**夹具目录：** `mobile/tests/fixtures/`（有 `.gdignore`，不进 PCK、不参与导入）。

**纯文本子集（毫秒级）：**

```bash
python3 tools/lint_core_purity.py mobile/src/core
python3 tools/gen_tap_golden.py --check
python3 tools/gen_geometry_golden.py --check
python3 tools/sync_config.py --check
```

## Sampling Rate

- **After every task commit:** `bash mobile/tools/test-core.sh`
- **After every plan wave:** quick + `bash mobile/tools/gate-a.sh` + `bash tools/check_desktop.sh`
- **After changing `test-core.sh`:** additionally `bash mobile/tools/test-core-selftest.sh`
- **Before `/gsd-verify-work`:** full suite green **and** the real-device checklist D0–D6 recorded in `mobile/ACCEPTANCE.md` §6
- **Max feedback latency:** ~40 s (quick) / ~6 min (full)

## Manual-Only Verifications

> Preconditions: `bash mobile/tools/gate-b.sh` needs `GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD` exported; artifact at `mobile/build/fifa-trainer.apk`. Record everything in `mobile/ACCEPTANCE.md` §6 (Phase 4).

| Behavior | Requirement | Why Manual | Test Instructions |
|----------|-------------|------------|-------------------|
| Fresh phone first launch → pair → wake by pressing any button | ONBOARD-01, success criterion 2 | Bluetooth pairing, Android input stack, and first-run state cannot be simulated | D0: `adb uninstall com.fifaskill.trainer`, install, launch, no docs; press any button on the controller; all four probe steps pass; center + full-scale calibration completes; nothing requires touching the screen |
| Axis probe persisted per device | INPUT-02, INPUT-03, success criterion 3 | Real axis indices/signs are device-specific and unmeasurable headless | D1: `adb shell run-as com.fifaskill.trainer cat files/profiles/controllers.json`; `axes.rs_x` / `axes.rs_y` index+sign match hand-pushed directions; **no device index field** |
| Different controller re-probes, never reuses | success criterion 3 (second half) | Requires two physical controllers | D2: swap controller A → B; app returns to probe instead of practice; second key appears; A unchanged. **Reuse gate must be observable on both sides**: same controller A reconnects → only right + down verification, then layout confirm (no four-step probe); use two controllers with different mappings (A = Xbox, B = DualSense), hand-edit B's `device_name` to equal A's → `reuse_mismatch` message and full four-step probe. Two identical controllers are not a valid counterexample (reuse is correct there). Seeing only one side means the gate is either always-reuse or always-reprobe |
| Layout suggestion + explicit confirmation | INPUT-04, success criterion 4 | Button index mapping differs by controller family | D3: Xbox → "Xbox layout" suggestion, press A; DualSense → "PlayStation layout", press ✕ (index 0); before confirmation a shot must produce no Outcome; record actual `get_joy_name()` strings |
| One green-finesse shot → exactly one verdict | success criterion 5 (first half) | The whole device→detector→banner path is only real on hardware | D4: hold RB, tap X twice ~450–500 ms apart; exactly one verdict; failure shows reason + measured ms. Counterexamples: 300 ms → `too_fast`; 700 ms → `too_slow`; release RB mid-way → `hold_short`; each must yield exactly one verdict |
| Two quick shots → two independent verdicts | success criterion 5 (second half) | Depends on cooldown + re-arm behaviour in real time | D5: two successful shots ≥1 s apart → two verdicts, `group_hits` 0→2. Also: whip RS right→left→right within ~50 ms → `events_motion` increases by ≥3 and Δt p95 ≤ 20 ms |
| Input health measurements | INPUT-02, INPUT-05 | Threading and timestamp granularity are Android-only facts | D6: read `events_motion` / `events_button` / `poll_edges` / `dt95` / `group_hits` from the practice screen `%DebugPanel`; read `dt50` / `dt95` / `dtmax` / `in_tid` / `proc_tid` / per-axis `v`·`min`·`max` / `get_joy_name` / `get_joy_guid` from `adb logcat -s godot:I | grep -E 'PAD_DIAG|PAD_AXIS|PAD_DEV'`.
