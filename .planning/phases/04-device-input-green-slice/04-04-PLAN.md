## 为什么新开 `mobile/src/input/`

`src/app/` 现在只有一件职责：持久化 I/O。输入设备是「读环境 + 有生命周期 + 可能跨线程」，混进去会让 `CORE.md` 的「I/O 只允许出现在 config_store.gd」变成假话。`src/input/` 天然允许 `Input.` / `Time.` / `Node`，而 core 不得反向依赖它 —— 依赖方向严格单向：`core ← input ← ui`，`app` 只做 I/O，`ui` 是唯一同时知道三者的组合根，零 autoload。

## 单切片说明

本计划的源文件与 `*.gd.uid` 边车同属一条设备输入链（缓冲 → 采样壳 → 档案存储 → lint 边界 → 闸门断言），且 `mobile/src/input/` 是新建目录；拆开会让「缓冲 + 薄壳」的幂等契约在中间态无法被测试。文件数多是有意的。

    `func reconcile(t_ms: float, polled_down: Dictionary) -> int`：对 0..20 逐索引比较 `bool(polled_down.get(index, false))` 与当前状态；不同则 `poll_edges += 1` 并 `_set_button(t_ms, index, down)`；返回本次补出的边沿数。**该函数必须幂等**：状态已一致时不产生任何变化（这就是「两条通道写同一份状态」的全部机制，不维护两套代码路径）。
