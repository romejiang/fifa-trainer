<objective>
让一台全新手机第一次打开应用时，用户只看屏幕就能走完「配对 → 按任意键唤醒 → 四步轴探测 → 中点 + 满量程校准 → 布局确认」，并在确认之前**进不去**练习。

Purpose: 成功标准 2 的原话是「全程不读文档」。这意味着引导必须把「为什么」也说清楚（安卓蓝牙手柄在收到第一次输入前不出现在设备列表里；校准要双手离开摇杆），并且每一步的失败都要给出具体原因而不是「重试」。同时成功标准 4 要求「必须用户按键确认后才进入练习」——本计划把这条做成状态机的不变量，界面只是渲染器。

Output: 一个纯状态机 `OnboardingFlow`（无头可测）、组合根 `main.gd` / `main.tscn`、引导屏 `onboarding_screen.gd` / `.tscn`、`project.godot` 的新主场景与显示设置、以及字体闭世界（`CHAR_SOURCES` 登记 + 机械断言）。

## 这一波的形状

先做**纯状态机并证明**（Task 1），再做**渲染器**（Task 2），最后**把字形闸门的闭世界缺口补上**（Task 3）。顺序不能反：如果先做界面，状态机会长在 `_process` 里，就再也无法在无头环境里证明「不触摸也能走完」。

## 单切片说明

本计划把「纯状态机 + 组合根 + 引导屏 + 字形闭世界」放在同一刀里，是因为任何一半单独落地都无法通过自己的闸门：状态机没有组合根就没有设备列表，引导屏没有状态机就只能把逻辑长进 `_process`，字形断言没有 UI 文件就没有可登记对象。`main.tscn` / `onboarding_screen.tscn` / `.gd` 与 `*.gd.uid` 边车都属于这一刀，随任务提交。

## 明确不做

- 不做自动推进 / 组进度点 / 音效 / 轨迹绘制（Phase 6 / 7）。
- 不做断连重连的完整 UX（Phase 8）；本阶段只做「检测到断开 → device_lost」的最小行为。
- 不做 badge / 动画 / 主题系统；字号常量足够。
- 不做多设备选择 UI：`get_connected_joypads()` 返回多台时只取第一台并把设备名显示出来（完整选择归 Phase 8）。

    方法（每个都要有明确的前置状态，非法时序直接 `return` 不改状态，不打印）：
    - `func on_device_list_changed(devices: Array, first_device_name: String, first_device_guid: String) -> void`：

    - `func rest_baseline() -> PackedFloat32Array`：返回 `rest`；未采集时返回空数组。`has_rest()` 供 UI 判断。
    - `func submit_probe_step(result: Dictionary) -> void`：`_has_rest` 为假时直接 return（防御）；`result["ok"]` 为真时存进 `_steps[key]` 并清失败字段，同时写 `quality[key] = {"samples": result["samples"], "margin": result["margin"], "separation": result["separation"]}`；四步齐了调 `ProbeEvaluator.validate_cross`，通过 → `STATE_CALIBRATE_CENTER`，不通过 → `STATE_PROBE_FAILED` 并把 `retry_state` 按 code 指向 `same_axis_up_right`→RIGHT、`vertical_not_opposed`→DOWN、`horizontal_not_opposed`→LEFT、其它→UP。`result["ok"]` 为假时 → `STATE_PROBE_FAILED`，`probe_failure_code = result["code"]`、`probe_failure_message = result["message"]`、`retry_state = 当前步`；**保留 `_steps` 里已完成的其它步**。
