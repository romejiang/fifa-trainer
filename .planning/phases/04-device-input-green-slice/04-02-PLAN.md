## 单切片说明

`Outcome` / `TapRuntime` / 运行时夹具 / 闸门反例 / `CORE.md` 契约同属一条判定链：没有运行时就没有「一次一条」的结构，没有夹具就没有对等证据，没有文档下一个读代码的人会把 `Frame.now` 改回毫秒。`*.gd.uid` 边车同属这一刀。

## 刻意的移动端改良（不是分歧）

Python 的 `Engine` 用 `last_outcome` + `outcome_seq`，同一帧若产生两条，第一条会被静默吞掉。移动端改为 `Array[Outcome]` 队列 + `pop_outcomes()` 全量 drain，并在每个 `Outcome` 上带单调 `seq`。「不丢结果」从约定变成结构；判定集合与 Python 完全一致。

## 刻意的范围收缩（必须写进代码注释，Phase 5 要还原）

`Frame` 本阶段只有 `now` 与 `buttons`，没有 `rs_mag`。因此：
- 手势锁按「右摇杆恒回中」的最保守路径实现：命中后固定锁满 `gesture_release_ms`（150 ms），锁满时调一次 `on_idle()`。
- `idle_reset_ms` 计时器**不移植**。论证：引擎的 idle 路径只调用 `on_idle()`，而 `TapDetector.on_idle()` 是空实现，所以对 tap 场景零行为差异；Phase 5 移植 arc / sequence 时必须补上。
- `_discard_other_claims`、`held_required`（别的技能的修饰键）、`relative_to_ls` 三处单技能场景下不可达，但 `relative_to_ls` 要留一道硬护栏：构造时若 `skill.relative_to_ls` 为真，运行时置 `_enabled = false` 并让 `tick()` 直接返回 —— 绝不在没有左摇杆基准的情况下判相对动作。
