  <action>
新建 `mobile/tools/gate-b-selftest.sh`，只做调度与断言，**不复制闸门 B 的任何检查逻辑**（需要完整验证时直接调 `gate-b.sh`）。体例照 `tools/verify_clean_clone.sh`：期望失败必须用 `if !` 包起来，绝不用 `|| true` 吞掉退出码后照样打印成功。

两个场景：

**场景 A —— 未签名残留过不了验签。** 绕过闸门的 `${VAR:?}` 守卫，直接用错误口令跑一次 Godot 导出（三个变量都设置但口令是错的），把它写到 `"$repo_root/mobile/build/unsigned-probe.apk"`。预期：Godot 退出码非 0，且磁盘上可能留下一个大小正常的包。收集事实并断言：
- 若文件存在，`apksigner verify` 对它必须**失败**（`if "$bt/apksigner" verify "$probe"; then 报错; exit 1; fi`）——这就是「文件存在 ≠ 成功」的现场证据。
- 若文件不存在，打印 `· 导出在写包前就失败了（同样安全）`，也算通过。
- 结束时 `rm -f "$probe"`，绝不把探针产物留在 `build/` 里。
场景 A 结束后重跑一次 `bash "$repo_root/mobile/tools/gate-b.sh"` 恢复一个合格产物。

**场景 B —— 口令不进日志。** 生成一个随机 canary 字符串（`LC_ALL=C tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 24`，前缀 `CANARY_`），把它当作 `GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD` 跑一次导出（必然失败），把 stdout+stderr 全部捕获到临时文件，然后断言该文件里**不出现**这个 canary。同时断言日志里出现了脱敏后的密钥库参数（`--ks` 后面不是真实路径或直接是脱敏占位；若实现只打印路径，至少要断言 canary 不出现——口令是唯一硬要求）。

两个场景都不许修改 `mobile/export_presets.cfg`、不许改环境里的真口令、不许把 canary 写进任何仓库文件。全部通过后打印 `SELFTEST_OK` 到 stdout 并 `exit 0`；任一失败打印 `SELFTEST_FAIL` 到 stderr 并 `exit 1`。
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| 构建机 → 仓库 | 密钥库文件与口令绝不能进入版本控制 |
| 导出日志 → 终端/CI | Godot 与 apksigner 的输出可能包含密钥库参数 |
| 导出器 → 磁盘 | 先写包、后签名；失败时可能留下未签名产物 |
| APK 内容 → 分发 | 包内可能混入 `.idsig`、debug 密钥库或 x86 库 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-10 | Information disclosure | release 密钥库与其口令 | critical | mitigate | 密钥库固定在仓库外路径并 `chmod 600`；口令只经 `-storepass:env` / `GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD` 传递；`.gitignore` 追加 `*.keystore` / `*.jks` / `*.idsig`；Task 3 用 canary 证明日志不含口令 |
| T-02-11 | Tampering | 导出失败后残留的未签名 APK | high | mitigate | 导出前 `rm -f`；导出后 `apksigner verify` 直接判退出码（不经管道）；Task 3 场景 A 现场证明「文件存在 ≠ 成功」 |
| T-02-12 | Spoofing | 用错 keystore / 别名签名 | high | mitigate | 包名 `com.fifaskill.trainer`、别名 `fifa-trainer`、versionCode 起始值全部定死；证书 SHA-256 抄进 SUMMARY 并在下一计划写进 BUILD.md 作为「同一把钥匙」的指纹；doctor 用 `-storepass:env` 验证别名可读 |
| T-02-13 | Information disclosure | APK 内混入签名旁文件或 x86 库 | medium | mitigate | `unzip -l` 断言无 `.idsig`、无 `.keystore` / `.jks`、无 `lib/x86*` / `lib/armeabi-v7a`；`aapt2 dump badging` 断言 `native-code: 'arm64-v8a'` |
| T-02-SC | Tampering | npm/pip/cargo 安装 | high | mitigate | 本计划零包管理器安装；所有工具来自已钉死版本的 Android build-tools 与 JDK 17 |
</threat_model>
