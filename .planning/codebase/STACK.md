# Technology Stack

**Analysis Date:** 2026-11-04

## Languages

**Primary:**
- Python `>=3.11` — entire application (7,030 lines across `main.py`, `app.py`, `padskills/*.py`, `tests/*.py`). Declared in `pyproject.toml` (`requires-python = ">=3.11"`). Uses modern typing (`from __future__ import annotations`, `list[str]`-era syntax), `dataclasses`, `pathlib`, `ctypes`.

**Secondary:**
- PowerShell (Windows build automation) — `build/build_windows.ps1`
- Bash (macOS build automation) — `build/build_macos.sh`
- JSON (user-facing rule configuration + lockfile) — `skills_config.json`, `uv.lock`
- Python-DSL spec file (PyInstaller) — `FIFA-Skill-Trainer.spec`

## Runtime

**Environment:**
- CPython 3.11+ (3.11 is the floor; wheels in `uv.lock` are cp311, and `uv sync` downloads a managed Python if needed)
- No async runtime, no web server, no background worker processes
- Single-threaded by design: SDL joystick/rumble/display calls must stay on the main loop thread (`padskills/rumble.py:242-257`, `padskills/gui.py:1-10`)
- Local developer machine currently has system Python 3.9.6 and uv 0.9.5 installed; the project itself is resolved through uv, not the system interpreter

**Package Manager:**
- `uv` (lockfile generated by uv; local version 0.9.5)
- Lockfile: present — `uv.lock` (lock format version 1, revision 3), pins exact resolved versions and hashes
- No `requirements.txt`, `poetry.lock`, `Pipfile`, or `setup.py`
- No virtualenv committed (`.venv/` is git-ignored)

## Frameworks

**Core:**
- `pygame-ce 2.5.8` — the only runtime framework. Wraps SDL2 and provides:
  - Window/rendering: `pygame.display`, `pygame.draw`, `pygame.font`, `pygame.time.Clock` (`padskills/gui.py`)
  - Gamepad input: `pygame.joystick.Joystick` (`padskills/input_source.py:357-553`)
  - Rumble: `Joystick.rumble()` / `stop_rumble()` (`padskills/rumble.py:48-65`)
  - SDL internals: `pygame._sdl2.controller.Controller.get_mapping()` (`padskills/input_source.py:569-602`), `Controller.rumble()` (`padskills/rumble.py:68-83`)
  - Event pump: `pygame.event.pump()` at 250 Hz (`padskills/input_source.py:486`)
- Stdlib-only supporting modules: `ctypes` (XInput DLL + Win32 console), `json`, `pathlib`, `dataclasses`, `argparse`, `re`, `subprocess`, `shutil`, `math`, `time`, `os`, `sys`

**Testing:**
- No test framework dependency. Tests are executable Python scripts with hand-rolled `check()` assertions (`tests/test_detectors.py:35-48`, `tests/test_gui_smoke.py:36-48`).
- `tests/test_detectors.py` — 1,480 lines, synthetic trajectory tests for detectors + engine + rumble state machine (README claims 127 checks)
- `tests/test_gui_smoke.py` — 466 lines, GUI smoke test using SDL dummy drivers (`SDL_VIDEODRIVER=dummy`, `SDL_AUDIODRIVER=dummy`)
- Run directly: `uv run tests/test_detectors.py`, `uv run tests/test_gui_smoke.py`
- No pytest, no unittest, no coverage tool, no CI runner

**Build/Dev:**
- `pyinstaller 6.22.3` (optional `build` extra) — produces single-file `.exe` / `.app`
- Transitive PyInstaller toolchain pinned in `uv.lock`: `pyinstaller-hooks-contrib 2026.9`, `altgraph 0.17.5`, `macholib 1.16.4`, `pefile 2024.8.26`, `pywin32-ctypes 0.2.3`, `packaging 26.3`, `setuptools 84.2.1` (platform-marked)
- `FIFA-Skill-Trainer.spec` — checked-in PyInstaller spec: entry `app.py`, `hiddenimports=['pygame._sdl2.controller']`, `excludes=['XInput']`, `console=False`, `name='FIFA-Skill-Trainer'`
- `build/build_windows.ps1` — `uv sync --extra build` then `pyinstaller --onefile --windowed --noupx`
- `build/build_macos.sh` — `uv sync --extra build` then `pyinstaller --windowed --noupx --osx-bundle-identifier com.fifaskill.trainer`
- No linter/formatter/type-checker configured (no ruff, black, isort, mypy, flake8 config; only their cache dirs are git-ignored)

## Key Dependencies

**Critical:**
- `pygame-ce>=2.5.8` — mandatory. Supplies SDL2 gamepad enumeration, HID mapping database access, window/rendering, and the primary rumble path. Without it nothing runs.
- `XInput-Python>=0.4.0` — optional extra (`uv sync --extra xinput`), Windows-only marker `sys_platform == 'win32'`. Used only as a fallback rumble backend (`padskills/rumble.py:144-168`), and explicitly excluded from PyInstaller bundles via `--exclude-module XInput`.
- `pyinstaller>=6.0` — optional `build` extra only; not imported at runtime.

**Infrastructure:**
- No database driver, ORM, HTTP client, web framework, message queue, or cloud SDK is installed.
- `ctypes` (stdlib) loads Windows system libraries directly: `Xinput1_4.dll` → `Xinput1_3.dll` → `Xinput9_1_0.dll` (`padskills/rumble.py:104-111`) and `kernel32` for console ANSI mode (`padskills/engine.py:42-50`).

## Configuration

**Environment:**
- No `.env` files exist; no secrets or API keys are used.
- Environment variables are process-local behavior switches, all optional:
  - `PYGAME_HIDE_SUPPORT_PROMPT=1` — set before importing pygame (`app.py:17`, `main.py:22`)
  - `SDL_VIDEO_CENTERED=1` — centers the GUI window (`padskills/gui.py:1286`)
  - `SDL_VIDEODRIVER=dummy`, `SDL_AUDIODRIVER=dummy` — test-only, set in `tests/test_gui_smoke.py:19-20`
  - `APPDATA` / `XDG_CONFIG_HOME` — read for per-user config directory resolution (`padskills/config.py:49-57`)
  - `PYGAME_HIDE_SUPPORT_PROMPT` and stdout handling also guard windowed PyInstaller builds where `sys.stdout`/`sys.stderr` are `None` (`app.py:17-24`, `main.py:24-36`)

**Application config:**
- Primary user config: `skills_config.json` (project root in dev; user config dir when frozen)
  - Dev path: repo root (`padskills/config.py:60-64`)
  - Windows frozen: `%APPDATA%\FifaSkillTrainer\skills_config.json`
  - macOS frozen: `~/Library/Application Support/FifaSkillTrainer/skills_config.json`
  - Linux: `$XDG_CONFIG_HOME/FifaSkillTrainer/` or `~/.config/FifaSkillTrainer/`
- Schema and validation live in `padskills/config.py`; built-in `DEFAULT_CONFIG` at `padskills/config.py:250-463` is the single source of truth, and `skills_config.json` is generated from it via `--write-config`.
- Runtime log: `<user_config_dir>/trainer.log`, UTF-8 with BOM, rotated by truncation at 2 MB (`padskills/gui.py:413-450`)
- CLI surface: `argparse` in `main.py:198-234` (`--gui`, `--debug`, `--trace`, `--list`, `--selftest`, `--write-config`, `--feedback`, `--no-rumble`, `--index`, `--duration`, `--config`)

**Build:**
- `pyproject.toml` — project metadata, dependencies, extras (`xinput`, `build`), no tool sections
- `uv.lock` — reproducible dependency graph
- `FIFA-Skill-Trainer.spec` — PyInstaller configuration
- `.gitattributes` — enforces LF for `.py/.json/.md/.toml/.lock/.sh/.spec`, CRLF for `.ps1`
- `.gitignore` — excludes `dist/`, `build/*` (except the two build scripts), caches, logs, editor dirs

## Platform Requirements

**Development:**
- Python 3.11+ and `uv`
- A physical gamepad for real testing (an Xbox-compatible controller; verified with Flydigi Vader 4 reporting as `Xbox One S Controller`, GUID recorded in README)
- macOS: Input Monitoring permission for the terminal or `.app` (System Settings → Privacy & Security → Input Monitoring)
- Linux: read access to `/dev/input`
- No display required for tests (SDL dummy driver); real GUI needs a display

**Production:**
- Windows `.exe` (single file, windowed) and macOS `.app` (unsigned, no notarization) — built natively on each OS because PyInstaller cannot cross-compile
- Per-user writable config/log directory; the app degrades gracefully if it cannot write (falls back to in-memory default config, `padskills/config.py:67-77`)
- No server, container, or cloud deployment target
