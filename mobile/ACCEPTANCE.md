# 真机验收表（闸门 C）

`mobile/tools/gate-a.sh` 与 `gate-b.sh` 只能证明**包**是对的：结构、字体覆盖、签名、对齐。
它们证明不了这个包在一台真实手机的 OEM 系统上会不会豆腐、能不能读到蓝牙手柄的原始轴。

这一页就是那部分。**它是唯一允许宣布「真机通过」的地方**，而且必须由人填。

---

## 第 0 节 前置条件（不满足就不许打勾）

四项全部为「是」之前，下面任何一格都不许勾。

- [ ] **设备状态可被检查**：`bash mobile/tools/doctor.sh device` 退出码为 0，且输出里有一行
      以 `✓ device` 开头。它不是构建闸门的一部分（导出不需要手机），只在这一节被点名运行。
- [ ] **两台不同 OEM 的手机**：不是两台同品牌同型号，也不是同一台刷了两次。
      分别记录厂商与型号：

      adb shell getprop ro.product.manufacturer
      adb shell getprop ro.product.model
      adb shell getprop ro.build.version.release

- [ ] **一只真手柄**：Xbox 或 DualSense，能与手机完成蓝牙配对（在系统蓝牙设置里能看到已连接）。
- [ ] **一条明确禁令**：**模拟器不算**，**单台手机不算**，**「上次装过所以肯定没问题」也不算**。
      这三件事都出现过，而且都能让一张表看起来填满、实际什么也没证明。

| 拒绝面后的重探 | 是否进入完整四步探针（`retry_state = PROBE_UP`；静止基线已采过，不再要求松手） | | | |
| 档案恢复 | 是否把 `/tmp/controllers-before.json` 推回并 force-stop 重启 | | | |

**拒绝面的唯一正确做法**：`ProfileStore.find(key)` 查的是
`DeviceProfile.make_key(device_guid, device_name)` 生成的**实时 key**，而档案在 JSON 里
**以外层 key 为索引**存。必须保留 A 条目的 `axes` / `calibration` 原值，把 A 条目的
**外层 key** 与内部 `key` / `device_guid` / `device_name` 一并改成 B 的值（若 B 已有
自己的条目，先删掉它，避免 JSON 出现重复键），推回后 force-stop 重启。
**只改 device_name 不会命中**：外层 key 仍是 A 的 guid，`find(B_key)` 直接查不到，
应用会走完整四步探针 —— 那看起来像「总是重探」，证明不了复用门有牙齿。

判定：两次都只看到完整四步探针 = 复用门没有生效（等价于总是重探）；拒绝面没有出现
`reuse_mismatch` = 复用门没有牙齿。两种都判失败。

| 项目 | 填写内容（可核对原文） | 验收时间 | 验收人 | 截图/录屏文件名 |
|------|------------------------|----------|--------|-----------------|

### **D6 输入体检（M1–M6）**

来源写死在本表里，不接受「设备看起来正常」作为替代：

- 练习屏 `%DebugPanel` 抄 `events_motion` / `events_button` / `poll_edges` / `dt95` / `group_hits`。
- `adb logcat -s godot:I | grep -E 'PAD_DIAG|PAD_AXIS|PAD_DEV'` 抄 `dt50` / `dt95` / `dtmax`、
  `in_tid` / `proc_tid`、每根轴的 `v` / `min` / `max`（扳机静止值取对应的 `v`）、
  `get_joy_name()` / `get_joy_guid()`。

**若 `PAD_DIAG` 行不存在，D6 判失败** —— 1 Hz 诊断日志是这些测量的唯一可抄录来源。
