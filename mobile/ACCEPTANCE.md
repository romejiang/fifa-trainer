# 真机验收表（闸门 C）

`mobile/tools/gate-a.sh` 与 `gate-b.sh` 只能证明**包**是对的：结构、字体覆盖、签名、对齐。
它们证明不了这个包在一台真实手机的 OEM 系统上会不会豆腐、能不能读到蓝牙手柄的原始轴。

这一页就是那部分。**它是唯一允许宣布「真机通过」的地方**，而且必须由人填。

---

## 第 0 节 前置条件（不满足就不许打勾）

四项全部为「是」之前，下面任何一格都不许勾。

- [ ] **设备状态可被检查**：`bash mobile/tools/doctor.sh device` 退出码为 0，且输出里有一行
      以 `✓ device` 开头。它不是构建闸门的一部分（导出不需要手机），只在这一节被点名运行。
- [ ] **两台不同 OEM 的手机**：不是两台同品牌同型号，也不是同一台刷了两次。
      分别记录厂商与型号：

      adb shell getprop ro.product.manufacturer
      adb shell getprop ro.product.model
      adb shell getprop ro.build.version.release

- [ ] **一只真手柄**：Xbox 或 DualSense，能与手机完成蓝牙配对（在系统蓝牙设置里能看到已连接）。
- [ ] **一条明确禁令**：**模拟器不算**，**单台手机不算**，**「上次装过所以肯定没问题」也不算**。
      这三件事都出现过，而且都能让一张表看起来填满、实际什么也没证明。

### 动作名覆盖方式（这一屏为什么只显示 5 这个数字）

**动作名的中文覆盖是机械覆盖**，不是靠这一屏逐条列出来：

- `tools/make_font_subset.py` 把 `shared/skills_config.json` 里的五个动作名连同 `_readme`
  一起抽进 `required_glyphs.txt`；
- 字形闸门（`mobile/tools/glyph_coverage.gd`）再对清单里的每个字符逐字符断言可渲染；
- 首屏只显示 `SKILL_COUNT = 5` 与最长中文串，**不逐条列出五个动作名**。

这是刻意的设计选择：这个屏是一次性验收面板，不是 UI。写在这里是为了让下一个人
不要以为成功标准 2 少测了一半 —— 动作名的字符已经由机械闸门覆盖，这一屏负责的是
「真实 OEM 字体回退下，最长的那一串和五个符号有没有塌」。

## 第 3 节 失败怎么记

不要写「有点问题」「基本正常」。每一处失败记三件事：

1. **哪一项**（①②③④ 或第 0 节的某条前置条件）；
2. **看到什么**（屏幕上的原文，或「显示为 3 个方框」，逐字抄，不要转述）；
3. **截图文件名**（该手机对应的 `device-smoke-<serial>.png`；必要时补拍一张屏幕照片，
   文件名写进同一格）。

失败项保持未打勾，**阶段不得声称完成**。修完之后重跑脚本、重新观察、重新记录 ——
不要把上一次的勾当作这一次的证据。

## 第 4 节 密钥库离线备份

这是成功标准 5 的前一半。四行都必须有内容；**任何一行留空即视为成功标准 5 未闭合**。

| 项目 | 填写内容（可核对的字符串） | 确认人 / 日期 |
|------|---------------------------|---------------|
| 备份 1 位置 | 介质类型 + 存放地点 + 备份日期（例：U 盘 / 家中抽屉 / 2026-11-04） | |
| 备份 2 位置 | 介质类型 + 存放地点 + 备份日期，必须与备份 1 **不同址或不同设备** | |
| 口令存放位置 | 密码管理器名称 + 条目名（**本表不写口令本身，也不写任何口令提示**） | |
| 最近一次恢复演练 | 从备份拷回临时目录、`keytool -list` 能打开、别名与指纹对得上、删除临时副本 —— 记日期与结果 | |

判定：两处介质互不同址或不同设备，且口令与密钥库文件**分开**存放。只写「已备份」
不算 —— 那不是可核对的字符串。

恢复演练怎么做：

    cp "<备份介质>/release.keystore" /tmp/restore-check.keystore
    chmod 600 /tmp/restore-check.keystore
    keytool -list -alias fifa-trainer -keystore /tmp/restore-check.keystore \
      -storepass:env GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD
    rm -f /tmp/restore-check.keystore

证书 SHA-256 应与第 2 节抄录的那串一致。
